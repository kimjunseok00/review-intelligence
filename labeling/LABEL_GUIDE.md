# 라벨 기준서 (초안)

사람 라벨과 AI 분류가 **같은 기준**을 쓴다. AI 프롬프트(`prompts/classify.txt`)도 이 문서를 옮긴다.
예비 라벨링 30건 후 의견이 갈린 사례를 "판단 사례"에 추가하고 버전을 올린다.

- 버전: v0.1 (초안, 예비 라벨링 전)

## 1. 감정 (하나만 고른다)

| 값 | 기준 |
|---|---|
| `positive` 긍정 | 전체적으로 만족. 작은 아쉬움이 있어도 추천·재구매 의사가 보이면 긍정 |
| `negative` 부정 | 전체적으로 불만. 반품·교환·환불 언급, "다시 안 산다" |
| `neutral` 중립 | 만족·불만 어느 쪽도 뚜렷하지 않음. "무난해요", "보통", 사실 나열만 있음 |

- **평점을 보지 않고 본문만으로 판단한다.** 평점과 본문이 다른 리뷰가 많고, AI도 본문만 받는다.

## 2. 불만 유형 (해당하는 것 모두, 없으면 비워 둔다)

| 값 | 이름 | 포함 | 포함하지 않음 |
|---|---|---|---|
| `delivery` | 배송 | 늦은 배송, 오배송, 배송 기사 문제, 누락 | 포장 상태(→ packaging) |
| `defect` | 품질·불량 | 고장, 파손, 하자, 금방 망가짐, 마감 불량, 냄새 | 받을 때부터 깨진 경우의 포장 문제는 packaging도 함께 |
| `mismatch` | 사이즈·설명 불일치 | 사이즈가 안 맞음, 사진·설명과 다름, 색상 차이 | 단순 취향("제 스타일 아니에요" → 불만 없음) |
| `price` | 가격 | 비싸다, 가격 대비 별로, 가격 변동 불만 | "가성비 좋아요"(불만 아님) |
| `packaging` | 포장 | 박스 파손, 포장 부실, 과대 포장, 뜯긴 흔적 | |
| `service` | 고객응대·교환반품 | 문의 무응답, 불친절, 교환·환불 지연 | 단순히 "반품했어요"만 있으면 반품 원인 유형만 |
| `other` | 기타 | 위 유형에 안 맞는 뚜렷한 불만 | 막연한 "별로예요"(→ 감정만 negative, 유형 없음) |

## 3. 판단 원칙

1. **불만이 문장에 드러나야 붙인다.** 추측하지 않는다.
2. **긍정 리뷰에도 불만 유형이 붙을 수 있다.** "제품은 좋은데 배송이 일주일 걸렸어요" → positive + delivery
3. **같은 리뷰에 여러 유형이 가능하다.** "박스가 찢어져 왔고 안에 제품도 깨져 있었어요" → packaging + defect
4. **애매하면 붙이지 않는다.** 놓치는 것(재현율 손실)보다 잘못 붙이는 것(가짜 급증)이 판매자에게 더 해롭다.

## 4. 판단 사례 (예비 라벨링 후 추가)

| 리뷰 | 감정 | 불만 유형 | 이유 |
|---|---|---|---|
| 디자인 예쁘고 가볍네요 만족합니다 | positive | - | |
| 생각보다 사이즈가 작아요 한 치수 크게 사세요 | neutral | mismatch | 조언 형태지만 사이즈 불만이 드러남 |
| 무난해요 | neutral | - | |
| 포장이 엉망이고 안에 제품도 깨져서 왔어요 | negative | packaging, defect | 원칙 3 |
| 비싸지만 품질은 괜찮아요 | positive | price | 원칙 2 |

(위 예시는 팀이 만든 가상 문장이다.)

## 5. 라벨 파일 형식

`labeling/raw/labels_<이름>.csv` (저장소에 올리지 않음)

```
review_id,sentiment,complaints
r-0001,negative,packaging;defect
r-0002,positive,
```

- `complaints`는 세미콜론으로 구분, 없으면 빈칸.
- **다른 팀원의 라벨을 보지 않고** 각자 작성한다. 보고 나면 일치도가 부풀려진다.
