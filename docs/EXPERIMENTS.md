## 실험 1. 사람 간 라벨 일치도

- 재료: 공개 리뷰에서 무작위 200건(seed 고정). 예비 라벨링 30건은 이 200건과 겹치지 않게 뽑는다.
- 방법: 팀원 3명이 `labeling/LABEL_GUIDE.md`로 서로 보지 않고 라벨링.
- 지표 (`experiments/metrics.py`)
  - 감정: Fleiss' kappa (3명)
  - 불만 유형: 유형마다 "해당/비해당"으로 나눠 각각 Fleiss' kappa
- 합의 라벨: 3명 중 2명 이상이 고른 값. 감정이 3명 모두 다르면 함께 논의해 정한다.
- 사전 기준: 감정 kappa ≥ 0.6. 미달이면 기준서를 고치고 다른 리뷰로 다시 한다.

## 실험 3. 분석 시간

- 수작업: 팀원 1명이 리뷰 200건을 분류하고 불만 유형별로 집계하는 시간을 잰다.
- 서비스: 같은 200건을 업로드부터 결과 화면까지 걸린 시간.
- 절감률 = (수작업 - 서비스) / 수작업 × 100. 측정값만 쓴다.

## 실험 4. 급증 탐지 (주입 실험, `experiments/inject.py`)

날짜는 가상이다. 이 실험은 탐지 규칙의 검증이며 실제 판매 현장 검증이 아니라고 발표에서 밝힌다.

1. 공개 리뷰 N건에 8주치 가상 날짜를 고르게 붙인다(`assign_dates`, seed 고정).
2. **사람이** 특정 유형(예: packaging)으로 라벨링한 리뷰를 주입 재료로 쓴다.
3. 특정 주에 그 유형 리뷰를 주당 리뷰 수의 5%, 10%, 20%만큼 주입한다(`inject_spike`).
4. 전체를 서비스에 넣고 `detect_spikes` 결과를 정답과 비교한다.
5. seed를 바꿔 조건마다 20회 반복한다.

| 주입 비율 | 탐지율 (주입한 주를 잡은 비율) | 오경보 (주입 안 한 주에서 울린 횟수 / 전체 주) |
|---|---|---|
| 5% | | |
| 10% | | |
| 20% | | |

- 사전 기준: **주당 리뷰 50건 이상**에서 20% 주입 탐지율 ≥ 0.8, 오경보율 ≤ 0.05
- 주당 리뷰 수가 20건 미만이면 판정 보류가 나온다. 주당 리뷰 수 조건도 표에 적는다.

### 사전 모의 계산 (2026-11-17, 분류 오류 없음 가정)

기본 불만 비율 5%, 2,000회 반복. `core/stats.judge_change`의 판정 규칙만 시험한 값이다.
실제 실험에서는 AI 분류 오류가 더해지므로 이보다 낮게 나올 수 있다.

| 주당 리뷰 | 5% 주입 | 10% 주입 | 20% 주입 | 오경보율 |
|---|---|---|---|---|
| 30건 | 0.05 | 0.11 | 0.53 | 0.004~0.006 |
| 50건 | 0.07 | 0.29 | 0.81 | 0.009~0.013 |
| 100건 | 0.25 | 0.63 | 0.99 | 0.021~0.024 |

해석:
- 오경보는 모든 조건에서 5% 아래다. 규칙이 보수적으로 잘 잡혀 있다.
- 대신 **리뷰가 적은 판매자는 주 단위로는 작은 급증을 못 잡는다.** 주당 30건이면 20% 급증도 절반만 잡는다.
- 대응: 리뷰가 적은 상품은 월 단위(`freq="M"`)로 집계하도록 화면에서 안내한다. 발표에서는 "주당 리뷰 50건 이상이면 20% 급증을 80% 확률로 잡는다"처럼 조건을 붙여 말한다.
